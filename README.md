# server-pet

A virtual pet that lives in your Discord server. One pet per server, shared by
everyone. Its stats fall in real time whether or not anyone is watching, and if
its health reaches zero it dies for good and gets a headstone.

Written in Rust with [Serenity](https://github.com/serenity-rs/serenity) 0.12
and SQLite.

## Running it

1. Create an application at the [Discord developer portal](https://discord.com/developers/applications),
   add a bot, and copy the token.
2. Invite it with the `bot` and `applications.commands` scopes. It needs
   **Send Messages**, **Embed Links** and **Attach Files** in whichever channel
   you point alerts at. No privileged intents are required.
3. Configure and run:

```bash
cp .env.example .env    # then paste your token into DISCORD_TOKEN
cargo run --release
```

Set `DEV_GUILD_ID` to your server's id while developing: guild commands appear
immediately, whereas global commands can take up to an hour to propagate.

## Commands

| Command | Who | What it does |
| --- | --- | --- |
| `/adopt` | anyone | Bring home a new pet. Blocked while one is alive. |
| `/pet` | anyone | The status card: stats, mood, age, and what it needs. |
| `/feed` | anyone | Restores hunger. Choose a snack, meal, treat or greens. |
| `/play` | anyone | Restores happiness, costs energy. Fetch, puzzle or dance. |
| `/rest` | anyone | Toggles a nap. Sleeping recovers energy. |
| `/heal` | anyone | Restores health. Long cooldown. |
| `/caretakers` | anyone | Who has done the most for the current pet. |
| `/graveyard` | anyone | Pets that came before. |
| `/pethelp` | anyone | In-Discord summary of all of this. |
| `/petrename` | Manage Server | Rename the pet. |
| `/petimage` | Manage Server | Replace the artwork with an image URL. |
| `/petalerts` | Manage Server | Pick the channel for warnings, or turn them off. |
| `/petrelease` | Manage Server | Retire the current pet so a new one can be adopted. |

## How the pet works

Four stats run from 0 to 100, and **higher is always better** - `hunger` is how
*fed* the pet is, so a full bar means a full belly.

- **Hunger** falls about 4 points an hour.
- **Happiness** falls about 3 points an hour.
- **Energy** falls about 5 points an hour. At zero the pet falls asleep on its
  own rather than taking damage, and sleeping restores it quickly.
- **Health** only moves in response to the others. It drains while hunger or
  happiness sit at zero, and slowly recovers while the pet is comfortable.

From full stats, a completely ignored pet gets visibly hungry after about 19
hours, starts taking damage at 25, and dies at around 41. A server has to miss
more than a full day before anything is irreversible.

Decay is calculated from elapsed time, not from a timer, so it is exact across
restarts and downtime. The background sweep exists only so the pet can ask for
help and so a death is announced when it happens.

Caring for the pet earns care points and levels it up, and **care is worth more
when the pet actually needs it** - feeding a starving pet scores roughly double
what topping up a full one does. Levels drive life stages, from Baby to Elder.

Tune any of this in `.env`; the rates live in `Rates` in
[`src/simulation.rs`](src/simulation.rs). Set `TIME_SCALE=100` to watch a whole
life play out in minutes.

## Artwork

**This is the part you will want to change.** The art that ships here is
placeholder: flat vector-ish shapes generated by a script, good enough to see
the system working.

Art lives under `assets/pets/` and is looked up by **species**, **life stage**
and **mood**:

```text
assets/pets/
  _default/           used when a species has no art of its own
    default.png
  blob/
    default.png       covers every mood with no file of its own
    happy.png
    sleeping.png
    baby/             optional per-stage overrides
      happy.png
```

Resolution takes the first file that exists, most specific first:

1. `<species>/<stage>/<mood>`
2. `<species>/<stage>/default`
3. `<species>/<mood>`
4. `<species>/default`
5. `_default/<mood>`
6. `_default/default`

So a species with a single `default.png` works, a fully illustrated one with
per-stage sprites works, and everything in between needs no configuration.
Moods are `happy`, `content`, `hungry`, `sad`, `tired`, `sick`, `sleeping` and
`dead`. Stages are `baby`, `child`, `teen`, `adult` and `elder`. Accepted
extensions are `.png`, `.gif`, `.webp`, `.jpg` and `.jpeg`.

Drop your own files in with those names and they are picked up on the next
restart. The bot logs which species are short of art at startup, and a test
(`the_shipped_art_covers_every_species_mood_and_stage`) fails if a file the
manifest expects has gone missing.

To regenerate the placeholders:

```bash
pip install pillow
python tools/generate_placeholder_art.py --force
```

`/petimage` is the escape hatch: it points one server's pet at any HTTPS image
URL, overriding the local art entirely.

### Adding a species

Add a table to [`assets/species.toml`](assets/species.toml), create
`assets/pets/<key>/`, and restart:

```toml
[[species]]
key = "otter"
name = "Otter"
emoji = "🦦"
description = "Busy. Extremely busy."
favourite_food = "meal"     # snack | meal | treat | greens
favourite_game = "fetch"    # fetch | puzzle | dance
```

The key must be letters, digits, underscores or hyphens, and it must match the
art folder name. Discord allows at most 25 choices on a command option, so at
most 25 species. A restart is needed because slash-command choices are fixed
when the commands are registered.

## Layout

| File | What is in it |
| --- | --- |
| [`src/model.rs`](src/model.rs) | Pet, stats, moods, life stages, levelling |
| [`src/simulation.rs`](src/simulation.rs) | Decay, recovery, death |
| [`src/state.rs`](src/state.rs) | Shared state; the only sanctioned way to read a pet |
| [`src/db.rs`](src/db.rs) | SQLite queries |
| [`src/images.rs`](src/images.rs) | Art indexing and the lookup chain |
| [`src/species.rs`](src/species.rs) | The species manifest |
| [`src/ui.rs`](src/ui.rs) | Embeds, stat bars, durations |
| [`src/commands/`](src/commands) | Slash command registration and handlers |
| [`src/ticker.rs`](src/ticker.rs) | Background sweep and alerts |
| [`migrations/`](migrations) | Schema, applied at startup |

## Tests

```bash
cargo test
```
